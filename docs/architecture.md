## Принципы

1. **Настройка — JSON, а не Lua.** Всё, что может захотеться поменять, — в `settings.jsonc`, с пояснением в
   `defaults.jsonc`.
2. **Применилось сразу.** Сохранили настройки — изменение видно без перезапуска везде, где это возможно.
3. **Быстро.** Код на экране через ~70 мс после запуска, буква — через ~6 мс после нажатия: плагины грузятся
   лениво (дополнение — при первом наборе), украшения (git-полоски, цветные скобки, TODO, липкая шапка, линтер) —
   после первой отрисовки, внешние программы — асинхронно.
4. **Своё там, где плагин мешает.** Статусная строка, вкладки, дерево файлов, темы, иконки, задачи, `.http`-клиент,
   эндпоинты, Docker — свой код; плагины — где они хороши (lazy.nvim, snacks, blink, conform, nvim-lint, neotest, dap…).
5. **Ошибка не ломает редактор.** Неверная настройка подсвечивается, редактор работает на прошлых настройках.

## Go-ядро и мост

Логика переносится с Lua на Go по частям. Уже на Go: движок настроек, Docker в коде, эндпоинты Gin, `.http`-клиент —
последние три написаны на `core/sdk`, как любое своё расширение ([Расширения на Go](go-extensions.md)). Lua остаётся тонкой связкой — то, что работает на каждой отрисовке
и клавише, конфиги плагинов, регистрация клавиш и событий.

- **Сборка.** `ownvimd` собирается в `~/.local/share/ownvim/ownvimd`: при первом запуске — сразу (`go build`), после
  правки Go-кода — в фоне, через секунду после первой отрисовки (`own.core.rebuild_async`).
- **Команды** — для того, что нужно синхронно и без состояния: `require("own.core").run({ "settings", "load", … })`.
- **Мост** — для модулей, которым нужно говорить с Neovim: `ownvimd serve` запускается при первом вызове,
  `require("own.core").request("метод", …)` ждёт ответа, `.notify` — без ответа. Вызов стоит ~0,01–0,05 мс, первый
  (с запуском процесса) — ~3 мс. Новый метод — `bridge.Register("имя", func(…) (…, error))` в Go.
- **Настройки** нужны до загрузки плагинов, а запуск процесса дороже чтения файла, поэтому Go пишет результат в
  `own-settings.cache.json` вместе с отпечатком исходных файлов (время изменения и размер `defaults.jsonc`,
  `settings.jsonc`, `own-auto.json`, списка опций, папки модулей и самой программы). На старте Lua сверяет отпечаток
  (несколько `stat`) и читает кэш — 0,6 мс против 3 мс у прежнего Lua-движка; Go запускается, только если что-то
  поменялось (+~7 мс один раз).
- **Тесты ядра:** `cd core && go test ./...`.

## Порядок старта

```
1. настройки       кэш Go-ядра (или ownvimd settings load, если файлы поменялись): умолчания + JSONC-наборы
                   + автоустановка + settings.jsonc  →  settings.current
2. globals, options до плагинов: leader должен быть известен заранее
3. lazy.nvim       плагины включённых модулей (M.plugins) + раздел plugins
4. модули          M.setup(opts) каждого включённого модуля, по алфавиту; упал — предупреждение, не ошибка
5. тема, клавиши
6. служебное       заметки, дерево, автоустановка, :Settings, :OwnHealth
7. слежка          сохранили settings.jsonc или defaults.jsonc → перечитать → применить
```

## Настройки: слои и применение на лету

`settings.load()` берёт результат Go-ядра (`core/settings`): оно читает оба файла, проверяет верхний уровень, имена
модулей и опций (список опций пишет Lua в `own-options.json`) и сливает:

```
merge(merge(defaults, auto_layer), user)
```

- `merge` — объекты по ключам, остальное заменяется; `true` поверх объекта оставляет объект; `{}` — пустой объект.
- `auto_layer` — языки, которые ownvim включил сам (`auto.lua`, файл `own-auto.json`): серверы в `lsp.servers`,
  форматтеры и линтеры по языкам. Слой лежит под `settings.jsonc`, поэтому пользователь всегда сильнее.
- Ошибки — в `settings.problems` (путь → диагностика); показываются на строках открытого файла настроек.
  `settings.warn(ключ, текст)` находит ключ в `settings.jsonc`, затем в `defaults.jsonc`.
- `settings.set(ключ, значение)` — `ownvimd settings set`: записать значение верхнего уровня в `settings.jsonc`,
  не трогая комментарии вокруг (ищется ключ именно верхнего уровня, одноимённые вложенные не трогаются).

При сохранении `init.on_change(new, old)` применяет globals и options, вызывает `M.reload(opts)` каждого модуля,
тему и клавиши. Если поменялся набор модулей или раздел `plugins`, просит `:restart`.

## Модули

Контракт и правила — [Расширение → Свой модуль](extending.md#свой-модуль). Коротко:

| поле | когда вызывается |
|---|---|
| `plugins(opts)` или таблица | при сборке списка плагинов lazy.nvim |
| `setup(opts)` | при старте, после плагинов |
| `reload(opts)` | при сохранении настроек |

`opts` — объект `modules.<имя>` без `enabled`. Модуль включён, если значение `true` или объект без `"enabled": false`.

## Клавиши и действия

Раздел `keys`: `"режимы клавиша": что`. `keys.lua` разбирает значение: имя действия из `actions.lua` (функция +
описание), клавиши как есть, `:команда`, объект `{ do, desc, remap }` или `false`. Описание действия видно в
which-key, `пробел sk` и в [справочнике](keys.ru.md), который собирает `scripts/keys.lua`. Для русской раскладки
alt-сочетания дублируются автоматически (модуль `russian`).

## Темы

Тема ownvim — JSON: `palette` (цвета), `syntax` (роли кода → цвета), `groups` (любые группы подсветки), `include`
(наследование). `theme/groups.lua` строит из палитры все группы: интерфейс, синтаксис, treesitter, семантические
токены LSP, группы плагинов. `theme/vscode.lua` конвертирует тему VS Code (`tokenColors`, `semanticTokenColors`,
`colors`) в этот формат; `theme/install.lua` скачивает расширение с Open VSX / Marketplace. Каждая тема — обычная
colorscheme (`colors/` генерируется), поэтому работает `:colorscheme` и выбор `alt-s`.

## Программы: mason и автоустановка

- `tools.lua` — нужна программа: есть в PATH — берём; нет — ставим пакет mason (по имени сервера из реестра или по
  имени программы); взять неоткуда — предупреждение в настройках. Реестр mason не грузится на старте: пакеты
  серверов кэшируются в `own-lsp-packages.json`.
- Серверы ставятся при старте, если включены; форматтеры и линтеры — при первом открытии файла их языка.
- `auto.lua` — на `FileType` незнакомого языка: проверенный набор из `auto.languages` или поиск в реестре mason по
  `filetypes` конфигов nvim-lspconfig (серверы шире 6 языков отбрасываются). Решение пишется в `own-auto.json`,
  настройки перечитываются, и `lsp`, `format`, `lint` применяют их через `reload()`.

## Где что хранится

| путь | что |
|---|---|
| `~/.config/ownvim` | сам ownvim (ссылка на репозиторий) и `settings.jsonc` |
| `~/.local/share/ownvim/lazy` | плагины |
| `~/.local/share/ownvim/mason` | серверы, форматтеры, линтеры |
| `~/.local/share/ownvim/ownvimd` | Go-ядро (собирается само) |
| `~/.local/share/ownvim/own-settings.cache.json` | итоговые настройки и замечания с отпечатком исходных файлов |
| `~/.local/share/ownvim/own-options.json` | имена опций nvim для проверки раздела `options` |
| `~/.local/share/ownvim/own-auto.json` | языки, включённые автоматически |
| `~/.local/share/ownvim/own-notes.json` | заметки о неудобствах |
| `~/.local/share/ownvim/own-settings.schema.json` | JSON-схема для подсказок в настройках |
| `~/.local/state/ownvim/colorscheme` | тема, выбранная в `alt-s` |
| `~/.local/state/ownvim/sessions` | сессии проектов |
| `~/.local/state/ownvim/*.log` | логи: `lsp.log`, `mason.log`, `conform.log`, `dap.log`, `ownvimd.log` (мост)… |

## Проверка изменений

- **`:OwnHealth`** — настройки, программы, серверы, форматтеры, парсеры, шрифт, тема, скорость старта.
- **Скорость — как её видит человек**, в настоящем псевдотерминале (скрипт отвечает на запросы nvim, как Ghostty):
  - `python3 scripts/bench_paint.py <папка> main.go Println` — через сколько мс после запуска код нарисован на экране;
  - `python3 scripts/bench_typing.py <папка> main.go` — от нажатия клавиши во вставке до буквы на экране.
  Сравнить с прошлым коммитом: `git worktree add /tmp/base/ownvim HEAD`, затем `XDG_CONFIG_HOME=/tmp/base python3 …`.
- **Где время на старте:** `NVIM_APPNAME=ownvim nvim --startuptime /tmp/st.txt +qa main.go`; какие плагины
  загрузились и почему — `require("lazy.core.config").plugins[имя]._.loaded`.
- **Без интерфейса:** поведение удобно проверять так: `NVIM_APPNAME=ownvim nvim --headless -c 'luafile check.lua' файл`,
  где `check.lua` через `vim.defer_fn` ждёт загрузки, проверяет состояние (диагностики, extmarks, клиенты LSP)
  и пишет результат в файл.
- **Справочник клавиш** после правки `keys` — `scripts/keys.lua`.
